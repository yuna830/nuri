
## 사용 목적

카메라에서 촬영된 얼굴 이미지를 InsightFace 임베딩으로 분석하고, 등록된 어르신 사진 및 실종 신고 사진과 비교하여 유사인물을 감지하면 Spring 서버에 알림을 전송한다.

이 문서는 얼굴 인식 서버(`face_api.py`)가 어떻게 동작하고, Spring 서버 및 raspi-client와 어떻게 연동되는지 정리하기 위한 구현 메모다.

## 서버 구현 위치

```txt
raspi-client/face_api.py
```

## 관련 Spring API

```txt
POST /api/alerts/camera           — 얼굴 매치 알림 전송
GET  /api/missing-reports/face-targets  — 실종 신고 사진 목록 조회
GET  /api/seniors/face-photo-targets    — 어르신 등록 사진 목록 조회
```

## 전체 아키텍처

```txt
[카메라 / raspi-client]
        ↓ 이미지 전송
[face_api.py — FastAPI 서버]
        ↓ 임베딩 비교
  등록 얼굴 DB (메모리)
        ↓ 매치 감지 시
[Spring 서버 /api/alerts/camera]
        ↓
[보호자 / 복지사 알림]
```

## face_api.py 엔드포인트

| 엔드포인트 | 메서드 | 설명 |
|---|---|---|
| /api/face/verify | POST | 이미지 업로드 → 등록 얼굴과 비교 후 결과 반환 |
| /api/face/reload | POST | 등록 얼굴 임베딩 전체 재로드 |
| /api/face/compare-police | POST | 어르신 등록 사진 ↔ 경찰 실종 신고 사진 비교 |

## 비교 대상 3가지

서버 시작 시 아래 3가지 소스에서 얼굴 임베딩을 로드한다.

| 소스 | 설명 | 로드 위치 |
|---|---|---|
| KNOWN_FACE | `known_faces/` 폴더 내 로컬 사진 | 파일 시스템 |
| MISSING_REPORT | 실종 신고 등록 사진 | Spring `/api/missing-reports/face-targets` |
| SENIOR_FACE | 활성 실종 신고 어르신 등록 사진 | Spring `/api/seniors/face-photo-targets` |

## 로컬 얼굴 사진 파일명 규칙

```txt
{seniorId}_{이름}.jpg
예: 1_홍길동.jpg
```

파일명에서 seniorId와 이름을 추출하여 임베딩에 함께 저장한다.

## 서버 시작 처리 흐름

```txt
서버 시작 (startup)
↓
load_registered_embeddings()
↓
load_known_embeddings()       — known_faces/ 폴더 스캔
load_missing_report_embeddings() — Spring API 호출
load_senior_face_embeddings()    — Spring API 호출
↓
메모리에 임베딩 목록 저장
```

## 임베딩 캐시 처리

Spring에서 가져온 사진은 URL별로 임베딩을 캐시한다.

```txt
embedding_cache_by_url = {이미지 URL: 임베딩 벡터}
```

서버가 실행 중인 동안 같은 URL의 사진은 재임베딩하지 않는다.

`/api/face/reload` 호출 시 캐시를 유지한 채로 임베딩 목록만 갱신한다.

## /api/face/verify 처리 흐름

```txt
이미지 업로드 (multipart/form-data)
↓
InsightFace로 얼굴 검출
↓
검출된 얼굴 없음 → NO_FACE 반환
↓
얼굴 품질 검사 (estimate_upload_face_quality)
↓
품질 미달 → LOW_QUALITY 반환
↓
등록 임베딩 전체와 코사인 유사도 계산
↓
최고 유사도 기준으로 상태 판정
↓
MATCH 또는 CANDIDATE → 알림 전송 (쿨다운 확인 후)
↓
결과 반환
```

## 매치 판정 기준

| 상태 | 조건 | 의미 |
|---|---|---|
| MATCH | 유사도 ≥ 0.62 | 동일인 판정, 알림 전송 |
| CANDIDATE | 유사도 ≥ 0.55 | 유사인물 후보, 보호자 확인 필요 |
| BODY_CANDIDATE | 얼굴 불일치 + 의복 색상 일치 | 얼굴 인식 실패 시 의복으로 보완 |
| NO_MATCH | 유사도 < 0.55 | 미일치 |
| LOW_QUALITY | 품질 점수 미달 | 비교 대상에서 제외 |
| NO_FACE | 얼굴 미검출 | 비교 불가 |

## 얼굴 품질 검사 기준

| 항목 | 가중치 | 세부 기준 |
|---|---|---|
| 크기 | 30% | 얼굴 최소 100px 이상 |
| 블러 | 25% | Laplacian 분산 기준 |
| 밝기 | 20% | 평균 픽셀값 45~210 |
| 랜드마크 안정성 | 15% | 5개 랜드마크가 얼굴 영역 안에 있는지 |
| 정면 포즈 | 10% | yaw, 눈 기울기 기준 |

임계값:

```txt
등록 사진 (KNOWN_FACE_QUALITY_MIN_SCORE) = 0.45
실시간 촬영 (LIVE_FACE_QUALITY_MIN_SCORE) = 0.45
```

## 다중 얼굴 처리

한 장의 이미지에서 얼굴이 여러 명 검출된 경우 최대 10명까지 각각 비교한다.

```txt
얼굴 크기 내림차순 정렬 → 최대 10개 선택 → 각각 비교
```

실종자가 여러 명 찍힌 경우를 대비하여 모든 얼굴을 확인한다.

## 의복 색상 보조 판정 (BODY_CANDIDATE)

얼굴 유사도가 CANDIDATE 미만이어도 실종 신고에 의복 설명이 있는 경우 의복 색상으로 보조 판정한다.

```txt
얼굴 bbox 아래 영역 추출 (body_region)
↓
HSV 색상 공간으로 변환
↓
실종 신고 description의 색상 키워드와 비교
↓
전체 픽셀 중 해당 색상 비율 ≥ 15% → BODY_CANDIDATE
```

## 알림 전송 기준

매치 감지 시 Spring `/api/alerts/camera`로 알림을 전송한다.

```txt
seniorId
type = AI_CANDIDATE_CONFIRM
candidateKind = FACE_MATCH 또는 BODY_CANDIDATE
message = "유사한 사람이 감지되었습니다. 보호자 확인이 필요합니다."
```

## 알림 쿨다운

같은 어르신에 대해 알림이 반복 전송되는 것을 막는다.

```txt
쿨다운 = 600초 (10분)
```

10분 안에 같은 seniorId의 매치가 다시 감지되면 알림을 전송하지 않는다.

## /api/face/compare-police 처리 흐름

보호자 앱에서 어르신 등록 사진과 경찰 실종 신고 사진을 비교할 때 사용한다.

```txt
seniorId 수신
↓
Spring /api/seniors/{seniorId}/face-photos 호출
↓
어르신 등록 사진 최대 4장 임베딩
↓
평균 임베딩 계산
↓
MISSING_REPORT 소스 임베딩 전체와 유사도 비교
↓
missingReportId별 최고 유사도 반환
```

## 환경 변수

```txt
SPRING_SERVER_URL=http://localhost:8080
KNOWN_FACE_DIR=known_faces
```

## 오류 처리 기준

| 오류 상황 | 처리 방식 |
|---|---|
| 이미지 읽기 실패 | INVALID_IMAGE 반환 |
| 얼굴 미검출 | NO_FACE 반환 |
| 품질 미달 | LOW_QUALITY 반환 |
| Spring API 호출 실패 | 해당 소스 임베딩 빈 배열로 처리 |
| 이미지 URL 다운로드 실패 | 해당 사진 임베딩 스킵 |
| 알림 전송 실패 | 로그 출력 후 계속 진행 |
| 등록 임베딩 없음 | NO_KNOWN_FACE 반환 |

## 주의사항

실종자 원본 사진과 임베딩 데이터는 메모리에서만 관리하고 Obsidian에 저장하지 않는다.

`/api/face/reload`는 서버가 실행 중인 상태에서 새 얼굴 등록 또는 실종 신고 변경 시 호출해야 한다.

알림 쿨다운은 서버 재시작 시 초기화된다.

카메라 해상도가 낮거나 조명이 어두운 경우 품질 검사에서 LOW_QUALITY로 처리될 수 있다.

InsightFace `buffalo_l` 모델은 서버 시작 시 한 번만 로드하므로 초기 구동 시간이 걸릴 수 있다.

## 최종 정리

얼굴 인식 서버는 `face_api.py`가 FastAPI 서버로 동작하며, 서버 시작 시 로컬 사진·실종 신고·어르신 등록 사진 3가지 소스에서 얼굴 임베딩을 메모리에 로드한다.

`/api/face/verify`로 이미지를 받으면 InsightFace 임베딩과 코사인 유사도로 비교하고, 유사도 기준(MATCH ≥ 0.62 / CANDIDATE ≥ 0.55)에 따라 Spring 서버에 알림을 전송한다.

얼굴 인식이 어려운 경우 의복 색상 보조 판정(BODY_CANDIDATE)을 통해 보완한다.
