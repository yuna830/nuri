# 리콜제품 확인 방법

## 먼저 확인할 제품 정보

- 제조사 또는 수입사
- 제품명
- 모델번호
- 바코드 또는 제조번호
- 제조일자나 제조기간
- KC 인증번호

모델번호는 제품 본체의 명판, 바닥·뒷면 라벨, 배터리 덮개 안쪽, 포장 상자, 사용설명서에서 확인할 수 있다. 사진 OCR 결과는 오인식할 수 있으므로 사용자가 제품 라벨을 다시 확인하도록 안내한다.

## 확인 절차

1. Safety Korea 등 공식 리콜 정보에서 제조사와 제품명을 확인한다.
2. 모델번호를 공백·하이픈을 포함해 원문과 정확히 비교한다.
3. 공고에 제조기간, 제조번호 또는 바코드 범위가 있으면 해당 값도 확인한다.
4. 모든 필수 조건이 일치할 때만 리콜 대상으로 판정한다.

유사한 제품명이나 임베딩 검색 결과만으로 리콜 대상이라고 판단하면 안 된다. 실제 판정은 `recall_products` DB의 정확 일치 조회 결과를 사용한다.

## 정보가 불충분한 경우

모델번호나 제조기간을 확인하지 못하면 `NEEDS_REVIEW`로 안내한다. 제품을 임의로 분해하지 말고 제조사 또는 판매처에 확인한다.

## 리콜 확인에 사용하는 공식 정보

| 정보 | 용도 |
|---|---|
| 리콜 ID | 공고를 유일하게 식별 |
| 제조사·수입사 | 제품 공급 주체 확인 |
| 제품명 | 제품 종류의 1차 확인 |
| 모델번호 | 정확 일치 판정의 핵심 값 |
| 제조기간 | 같은 모델 중 대상 생산분 확인 |
| 바코드·제조번호 | 세부 대상 범위 확인 |
| 리콜 사유 | 결함과 위해 유형 설명 |
| 조치 내용 | 사용 중지, 수리, 교환, 환불 등 안내 |
| 공고 시작일·활성 상태 | 현재 유효한 리콜인지 확인 |

## 사진과 OCR을 사용할 때

1. 제품 전체 사진과 명판 사진을 따로 촬영한다.
2. 반사광이나 흔들림이 없도록 모델번호를 가까이 촬영한다.
3. OCR로 제조사, 모델번호, 제조일자 후보를 추출한다.
4. `O/0`, `I/1`, `B/8`, 하이픈과 공백 오인식을 보정 후보로만 생성한다.
5. 사용자에게 추출한 값을 보여주고 직접 확인받는다.
6. 확인된 값으로 DB 정확 일치 조회를 실행한다.

OCR 결과 자체를 최종 제품정보로 저장하거나 리콜 판정에 바로 사용하지 않는다.

## 서비스 판정 상태

| 상태 | 의미 |
|---|---|
| RECALL_CONFIRMED | 공식 공고와 필수 식별정보가 충분히 일치함 |
| NO_MATCH_FOUND | 정상 조회했지만 입력 정보와 일치하는 공고를 찾지 못함 |
| REVIEW_REQUIRED | 후보는 있지만 식별정보 또는 추가 조건 확인이 필요함 |

조회 상태는 판정과 별도로 관리한다.

| 조회 상태 | 의미 |
|---|---|
| SUCCESS | 공식 리콜 데이터 조회와 판정이 정상 완료됨 |
| FAILED | 인증키·네트워크·외부 서버·응답 처리 문제로 조회 실패 |
| NOT_CHECKED | 아직 조회하지 않음 |

`NO_MATCH_FOUND`는 제품의 안전성을 보증하지 않는다. API 조회 실패도 `NO_MATCH_FOUND`가 아니며 기존 판정 근거를 유지해야 한다.

## 서비스 입력 항목 예시

| 항목 | 설명 |
|---|---|
| manufacturer | 제조사 또는 수입사 |
| productName | 제품명 |
| modelNumber | 모델번호 |
| serialNumber | 제조번호 |
| barcode | 바코드 |
| manufacturedAt | 제조일자 |
| kcNumber | KC 인증번호 |
| ocrConfidence | OCR 인식 신뢰도 |
| userConfirmed | 사용자가 식별값을 확인했는지 여부 |

## 정확 일치 판단 로직

1. 제조사 또는 수입사를 정규화해 일치 여부를 확인한다.
2. 모델번호를 대소문자, 앞뒤 공백 등 안전한 범위에서 정규화한다.
3. 정규화된 모델번호가 정확히 일치하는 활성 리콜을 조회한다.
4. 공고에 제조기간 조건이 있으면 제품 제조일자가 범위 안인지 확인한다.
5. 바코드나 제조번호 조건이 있으면 해당 값도 정확히 비교한다.
6. 모든 필수 조건이 맞고 제조기간 등 추가 조건이 없을 때만 `RECALL_CONFIRMED`로 판정한다.
7. 정보가 빠졌거나 추가 조건을 자동 확인할 수 없으면 `REVIEW_REQUIRED`로 반환한다.
8. 유사 제품 검색 결과는 설명용 후보로만 보여주고 판정 근거로 쓰지 않는다.

## 사용자 질문 예시

- 이 밥솥 리콜 대상이야?
- 모델번호는 어디에서 확인해?
- 사진으로 리콜 여부를 알 수 있어?
- 제품명은 같은데 모델번호가 달라. 리콜이야?
- 제조기간도 확인해야 해?
- KC 번호로 리콜을 찾을 수 있어?

## RAG 검색 키워드

리콜제품 확인, 제품 리콜 조회, Safety Korea, 모델번호 확인, 제조번호, 시리얼번호, 바코드 리콜, 제조기간 리콜, 제품 명판, KC 인증번호, 전기제품 리콜, 어린이제품 리콜.

## 주의사항 및 출처 메모

공식 리콜 판정은 API·DB·명시적 규칙만 사용한다. RAG는 확인 방법과 조치 방법을 설명할 뿐 판정에 참여하지 않는다. 사용자에게 공식 출처와 마지막 정상 확인 시점을 함께 표시한다. DB에 일치 항목이 없다는 사실은 제품의 일반적인 안전성을 보증하지 않는다.
